Install

    
Needs Claude Code and Node.js 18 or newer. No bash, jq or python3 required. git is optional (branch and git status).

    
Already using it? Don't reinstall from scratch — use Update. It keeps your segments, order and theme, so the line looks the same afterwards. Breaking changes.

    

      
      
    

    
git clone https://github.com/FahimFBA/claudecode-statusline.git
cd claudecode-statusline
chmod +x install.sh
./install.sh

    
git clone https://github.com/FahimFBA/claudecode-statusline.git
cd claudecode-statusline
powershell -ExecutionPolicy Bypass -File install.ps1

    
Then restart Claude Code. Choose 1) Default (compact classic line), 2) Custom (type the component numbers in the order you want them, e.g. 2 3 4 6 7 10 13, or all) or 3) Install all (every segment plus git status). Each asks for a theme and shows a live preview before writing anything.


    
What the installer does

    
    
      
  1. Copies hook scriptsInto ~/.claude/hooks/, and removes a stale v1 caveman-statusline.sh.
    2. 
      
  2. Merges settingsInto ~/.claude/settings.json — existing file is backed up to settings.json.bak, only this project's entries are touched, your other hooks and config survive, re-running is safe.
    3. 
      
  3. Installs the Caveman pluginVia claude plugins install caveman --marketplace caveman.
    4. 
    

  






  

    
Update

    
Safe to run any time, and again after every git pull. The installer shows what is installed (Installed: v1.x → this version: v2.0.0), backs up settings.json first, and touches only this project's entries.

    

      
      
    

    
cd claudecode-statusline
git pull
./install.sh            # choose "4) Update" (the default)
./install.sh --update   # or: no questions asked

    
cd claudecode-statusline
git pull
powershell -ExecutionPolicy Bypass -File install.ps1           # choose "4) Update"
powershell -ExecutionPolicy Bypass -File install.ps1 -Update   # or: no questions asked

    
Then restart Claude Code. Check the installed version with node ~/.claude/hooks/caveman-statusline.js --version.


    

      
✅ Keeps
Your SL_* settings (hidden segments, SL_ORDER, SL_THEME), your other hooks, permissions, model and every other key in settings.json.

      
🔄 Replaces
The scripts in ~/.claude/hooks/. A leftover v1 caveman-statusline.sh is removed. Running Update twice changes nothing.

      
🆕 From 1.x
Nothing visible changes. The v2 extras — git status, burn rate, cost, time, lines — are off by default. Say y when asked to turn them on, or re-run and pick Install all later.

      
🛑 Refuses
To touch a settings.json that is not valid JSON. It stops and changes nothing.

    


    
Rolling back

    
Two backups sit next to settings.json: .bak (before the latest run, overwritten each run) and .pre-v2.bak (written once when you first upgrade from 1.x, never overwritten).

    
# macOS / Linux
cp ~/.claude/settings.json.pre-v2.bak ~/.claude/settings.json
git checkout v1.0.1 && ./install.sh     # old scripts back

# Windows (PowerShell)
Copy-Item "$env:USERPROFILE\.claude\settings.json.pre-v2.bak" "$env:USERPROFILE\.claude\settings.json" -Force
git checkout v1.0.1; powershell -ExecutionPolicy Bypass -File install.ps1

  






  

    
Customize

    
Re-run the installer and pick option 2, or set env vars in the statusLine command of ~/.claude/settings.json.

    

      

        
Env varDefaultEffect

        
          
SL_ORDER=allunsetEverything: all 12 segments plus git status. What "Install all" writes

          
SL_ORDER=a,b,cunsetShow only these segments, in this order. Keys: caveman project model ctx effort 5h 7d burn cost time lines savings. Add git for git status markers

          
SL_BURN=1 SL_COST=1 SL_TIME=1 SL_LINES=1 SL_GIT=1offSwitch a single extra on without listing everything (ignored when SL_ORDER is set)

          
SL_THEME=norddefaultdefault · nord · gruvbox · light · mono

          
NO_COLOR=1unsetNo colors at all

          
SL_GIT=0Hide git status markers, keep the branch (skips git status)

          
SL_CAVEMAN=0onHide caveman badge

          
SL_PROJECT=0onHide project + branch + git status

          
SL_MODEL=0onHide model name

          
SL_CTX=0onHide context window bar

          
SL_EFFORT=0onHide effort level

          
SL_5H=0onHide hourly rate limit

          
SL_7D=0onHide weekly rate limit

          
SL_BURN=0onHide burn-rate warning

          
SL_COST=0onHide session cost

          
SL_TIME=0onHide session time

          
SL_LINES=0onHide lines changed

          
SL_SAVINGS=0onHide token savings

        
      

    

    
How they combine: no SL_ORDER → the classic set (extras only with their SL_<X>=1); SL_ORDER=all → everything; SL_ORDER=a,b,c → exactly those. Then any SL_<SEGMENT>=0 removes what it names.

Uninstall

    
Run from your clone. Removes the hook files and only the settings.json entries this project added — your other hooks, plugins and config stay (the old file is saved as settings.json.bak).

    
macOS / Linux

    
./uninstall.sh              # asks first
./uninstall.sh --keep-plugin # leave the caveman plugin entries

    
Windows (PowerShell)

    
powershell -ExecutionPolicy Bypass -File uninstall.ps1
powershell -ExecutionPolicy Bypass -File uninstall.ps1 -Yes -KeepPlugin

    
To also remove the plugin itself: claude plugins uninstall caveman.
